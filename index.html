CONTEST RULES

Правила соревнования

Как проводятся тесты и по каким принципам считаются показатели
01 · Основной принцип

Одинаковые условия для нейросетей

В каждом режиме все участвующие нейросети получают один и тот же основной промпт. Текст задания, требования и исходные материалы должны быть одинаковыми. Цель — сравнить результаты моделей при равных стартовых условиях.

Для каждого режима используется свой промпт. Посмотреть его можно в карточке соответствующего теста.

02 · Промпты и правки

Основной запрос и дополнительные запросы

  • Основной промпт — первое задание, которое получает модель.
  • Дополнительная правка — каждый отдельный запрос после основного, который просит исправить, изменить или улучшить созданный сайт.
  • Один отправленный запрос считается одной правкой, даже если в нём перечислено несколько изменений.
  • Если после ответа нужно отправить ещё один корректирующий запрос, он считается следующей правкой.
  • Чтобы сравнение оставалось честным, желательно отправлять моделям одинаковые по смыслу дополнительные указания.
03 · Важное правило подсчёта времени

Время создания включает все этапы работы

Время создания сайта — это общее время, затраченное на получение финальной версии, а не только время первого ответа нейросети.

В подсчёт входят основной промпт, генерация первого результата, все последующие промпты, в том числе исправительные, и время генерации ответов на каждый из них. Если модель получила несколько запросов на доработку, время всех этих этапов суммируется.

Нельзя указывать только время создания первой версии, если после неё были дополнительные запросы и исправления. Для всех моделей в одном тесте нужно применять один и тот же способ замера.

04 · Количество правок

Как считать дополнительные правки

В поле «Дополнительные правки» указывается количество корректирующих запросов, отправленных после основного промпта. Сам основной промпт в это число не входит.

Например: основной промпт + три отдельных сообщения с исправлениями = 3 дополнительные правки.

05 · Объём кода

Строки, символы и среднее на строку

  • Строки кода — количество строк во всех текстовых файлах, которые входят в финальную версию сайта.
  • Символы — общее количество символов в этих исходных файлах. Для сопоставимости учитывайте пробелы и переносы строк одинаковым способом.
  • Среднее число символов на строку рассчитывается автоматически: общее количество символов делится на количество строк.
  • Изображения и другие бинарные файлы в подсчёт строк и символов исходного кода не входят.
Символов на строку = символы ÷ строки
06 · Названия моделей

Указывайте точную модель

В статистике следует записывать полное название использованной модели и, когда это применимо, её версию и режим работы (например, режим рассуждения). Не следует подменять точное название общим названием сервиса. Неизвестные характеристики не нужно угадывать.

07 · Как читать статистику

Общие показатели и показатели режима

  • Общая статистика объединяет заполненные результаты всех загруженных режимов.
  • Статистика режима сравнивает модели только внутри выбранного теста.
  • Суммарные значения складывают данные всех результатов, для которых соответствующее поле заполнено.
  • Средние значения рассчитываются только по результатам с указанными данными. Пустое поле не считается нулём.
  • Самое быстрое время, меньшее число правок или больший объём кода — это отдельные технические показатели, а не автоматическая оценка качества сайта.
08 · Заполнение данных

Точность и единый формат

  • Данные каждой работы записываются в соответствующий tests/название-режима/data.json.
  • Время указывается в секундах, количество правок, строк и символов — целыми числами.
  • Сложность задаётся целым числом от 0 до 12 в поле difficulty. Значение 0 означает минимальную, а 12 — максимальную сложность.
  • Дата выхода указывается в поле releaseDate в формате ГГГГ-ММ-ДД (например, 2026-11-17). Она используется для сортировки по дате.
  • Если показатель неизвестен или не измерялся, лучше оставить поле пустым или не указывать его, а не ставить приблизительное значение.
  • После добавления нового режима его папку нужно включить в tests/index.json, чтобы главная страница и статистика загрузили его.
